## this 포인터
![화면 캡처 2024-07-10 172846](https://github.com/gkeksd/codding-archive/assets/54362230/579012b1-ad39-4291-8348-966d007f55fb)
this 포인터는 포인터의 일종으로, 어떠한 (클래스의) 함수가 그것을 호출한 특정 객체의 데이터를 참조하기 위해 쓴다. 어떠한 함수 func1에 대해 그것을 호출한 객체 obj1의 data1을 참조한다면 해당 함수 내에 this->data1의 식으로 쓴다.

이 this를 쓰는 목적은, 멤버 초기화 리스트를 사용해 본문 이전에 초기화를 하는 것과 달리 본문 내에서 데이터 멤버의 값을 매개변수의 값으로 할당하고자 하는 경우 만약 두 변수의 이름이 동일하다면, 변수 가리기 효과(변수는 가장 가까운 곳에서 정의된 것을 따름)에 의해 매개변수 자기 자신에 의해 할당되게 되는 결과를 가져오기에 this를 사용해 두개를 명확히 구분해줄 수 있다.
```cpp
this -> name = name;
```
여기서 this로 참조된 첫번째 name은 데이터 멤버 변수 name이며, 피할당 변수 두번째 name은 매개변수 name이다.

## 정적 멤버
### 정적 데이터 멤버(Static data member)
정적 데이터 멤버란 클래스에 포함되는 데이터 멤버이기는 하나 클래스의 각 객체에 포함되지는 않는 멤버를 말한다.

정적 데이터 멤버는 객체와 무관하게 한개만 존재하며, 모든 객체가 공유한다. 따라서 한 곳에서 이 멤버의 값을 변경했다면, 해당 멤버의 값 자체가 변경되어 영향을 미친다.

일반적인 멤버 함수는 사실 개별 객체에 포함된 형태가 아닌 객체에 독립적으로 존재하여 개별 객체에 this 포인터를 통해 참조되는 형태인데, 정적 데이터 멤버도 비슷한 구조를 가진다.

따라서, 정적 데이터 멤버는 일반적인 데이터 멤버와는 달리 인스턴스화된 객체가 하나도 존재하지 않더라도 독립적으로 존재한다.

데이터 멤버를 초기화할때는 클래스 내에서 초기화하는 것이 아닌 멤버 함수들처럼 클래스 외부에서 초기화해야 한다. 다만, 정적 상수 데이터 멤버, 즉 static const 형에 대해서는 클래스 내부에서의 초기화도 가능하다.

### 정적 멤버 함수(Static member function)
일반적인 멤버 함수는 정적 데이터 멤버에 접근할 수 없기에, 정적 데이터 멤버에 접근하여 다룰 수 있는 멤버함수가 필요한데, 이것이 바로 정적 멤버 함수이다. 이 함수는 오직 정적 데이터 멤버에만 접근 가능하다.

함수 선언은 자료형 앞에 static을 붙이며, 함수 정의는 다른 함수와 똑같이 static을 붙이지 않고 한다. 한편 정적 데이터 멤버와 같이 인스턴스화된 객체가 없어도 독자적으로 존재할 수 있어야 하기에, 이 함수를 호출할 때는 객체.함수() 대신 클래스 이름::함수()의 형태로 호출한다.
```cpp
static int count(); //함수 선언
int Class::count() {} //함수 정의
Class::count(); //함수 호출
```

## 파일 분리
클래스와 멤버 함수, main 함수가 포함된 프로그램은 클래스 내용이 포함된 헤더 파일(.h), 멤버 함수가 정의된 .cpp파일, 기타 main 함수 및 기타 나머지 내용이 포함된 main.cpp 파일로 나눌 수 있다. 이때 두 cpp파일에서는 헤더파일을 include해서 사용한다.

헤더 파일의 includ는 다음과 같이 한다. 예를 들어 헤더 파일의 이름이 Temp.h라면
```cpp
#include "Temp.h"
```
보통 헤더파일과 멤버 함수 정의한 파일의 이름은 해당 클래스의 이름으로 정하며, 헤더 파일을 include 할때는 <>가 아닌 ""를 사용한다.

![화면 캡처 2024-07-10 201534](https://github.com/gkeksd/codding-archive/assets/54362230/13d243fe-e9ef-4d43-a496-187f0a9ca8a1)
이렇게 파일을 나눔으로서, 한 개의 클래스를 여러 파일에서 별도로 객체를 생성하고 여러 번 재사용해야 할 때 효과적으로 객체 지향 프로그래밍을 구현할 수 있다는 장점이 있다.

### 분할 컴파일
![화면 캡처 2024-07-10 201707](https://github.com/gkeksd/codding-archive/assets/54362230/51191c25-a38c-4a29-9409-ddeca1148ebf)
한편 파일을 분할하여 컴파일을 하는 것을 **분할 컴파일**이라고 하는데, 이 분할 컴파일은 각각 멤버 함수를 정의한 구현 파일과 main 함수가 들어있는 애플리케이션 파일에 각각 헤더 파일이 include 되면, 각각의 ccp 파일을 컴파일러가 개별적으로 컴파일해 객체 파일(.o)로 만든다. 이후 링커 과정에서 링커가 이 두 객체 파일을 링킹하여 최종적으로 실행 파일로 만들어진다.

### 중복선언 방지
중복선언이란, 헤더 파일을 포함한 전체 프로그램에서 같은 헤더 파일이 두번 이상 중복으로 include 되는 것을 의미한다. 이를 방지하기 위해 #ifndef-#endif를 붙여 한번만 헤더 파일이 실행되도록 조건문을 걸거나, #pragma once를 통해 두번째 include는 아예 실행되지 않도록 할 수 있다.
```cpp
#ifndef TMP_H
#define TMP_H

#include <string>

class Tmp {
private:
    int a;
    std::string s;
public:
    Tmp(int a, std::string s);
    void display() const;
};

#endif
```
```cpp
#pragma once

#include <string>

class Tmp {
private:
    int a;
    std::string s;
public:
    Tmp(int a, std::string s);
    void display() const;
};
```
ifndef를 사용할 때는 헤더 파일을 대문자로 파일이름_H 식으로 작성한다.

## 캡슐화(Encapsulation)
캡슐화란 사용자나 다른 사람이 바뀌어서는 안되는 중요한 데이터를 임의로 수정하거나 직접 접근할 수 없도록 private 영역에 선언한 후 멤버 함수를 통해 간접적으로 접근하도록 하여, 프로그램의 보안을 실현하는 방식이다. 일반적으로 데이터 멤버가 이 캡슐화의 대상이 되지만, 멤버 함수의 경우에도 경우에 따라 캡슐화시킬 수 있다.
